# First-contact public context and name Memory

## Outcome and boundary

First-contact creation must attempt public search with the observed name and
minimal source-grounded public context, then fetch relevant discovered sources
before presenting review. A name Memory candidate in the Memory creation flow
must retain exact source provenance and require human confirmation. Public
background remains tentative Session context; no automatic identity, biography,
Memory save, or external action is authorized.

## Baseline and approach

The image registry excluded the direct-chat counterparty; the host fallback
staged an empty Memory proposal and could bypass research. Production-entry
verification with a deterministic inspector and real PostgreSQL reproduced
zero research dispatches. The real configured TestFlight research socket
successfully discovered and fetched three public pages for the public-only
`Andrej Karpathy nanoGPT` query. Service availability was not the blocker.

Use one same-run governed research seam for model Memory creation, contact-only
creation proposals, and the default screenshot review. Admit exact header names,
conservative project identifiers, professional role shapes, and canonical public
profile handles. Unfamiliar work names currently fall back to name/profile-only
research; model category labels cannot authorize their transmission. Never send raw dialogue, sensitive details, or arbitrary model
category labels. Explicit no-search intent and cancellation/source revocation
win. Reuse fetched sources and keep authentic host completion records.
