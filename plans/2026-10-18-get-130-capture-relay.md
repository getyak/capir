# GET-130: a truthful macOS capture relay

## Outcome and scope

An intentional screenshot visibly travels from its real selected region to a real attachment slot, then shows admitted processing and source-linked, unconfirmed text clues from that same Session message. Direct capture still submits on release; preview still stays local until Send. Animation never owns submission, completion, identity, Memory, or any external action.

Implement the existing GET-130 contract in `getyak/capir`, from fetched `origin/main` `7f5dd629bf83bfd8f5e6cb7d76f1f4325af82dc6`, branch `codex/get-130-capture-magic`. Preserve the dirty primary checkout, GET-39, pending GET-160 and all other chats. The primary remote's old `getyak/talent-signal` URL resolves to `getyak/capir`; do not change it. No Pi/MiMo, replacement scheduler, new provider, screenshot collection service, or iOS Simulator.

## Observed baseline

- `CaptureSelectionResult` contains only cropped image, timestamp and preview. Region-to-pixel mapping already rejects cross-display crops, but the transient selected screen rectangle is lost. Full-screen images are owned by the selection panels and released on finish.
- `CaptureCoordinator` already owns stable intent/session/message/image identifiers, context/policy fences, encrypted pre-admission recovery, status reconciliation and bounded polling. Preserve that authority and its duplicate/unknown safeguards.
- `CaptureRuntime` observes that coordinator and presents a content-free status hint. `DesktopPetController` owns a nonactivating artwork panel; clicking currently opens the shared Web workspace. Add a deliberate capture entry without breaking click/drag or turning the pet into a second CRM.
- `CaptureReceipt` has status, image manifest and `resultRecorded`, with no text-clue producer. A successful boolean cannot produce person/company chips. The existing same-run image inspector has exact visible text and provider receipts; reuse its result, never inspect again for an animation.
- Preview currently permits crop/redaction but no editable objective. Add an optional bounded instruction without changing direct release semantics or exposing native capture commands to page JavaScript.

### Chosen architecture

1. Add optional ephemeral region provenance beside selection results: display ID, selected global AppKit point rectangle and scale metadata. Keep pixel crop mapping separate from UI point conversion. Window capture/import/paste has no invented origin. Do not persist screen coordinates or full-desktop images into an intent, Agent payload, logs or telemetry.
2. Add a presentation projection and native relay controller, using the existing coordinator's stable intent and owner revision. A small purpose-specific capture surface near the visible pet can own an actual measured attachment slot; preview reuses the existing editor. Where no safe real slot exists, use the existing bounded handoff indication. The shared Web Session remains the canonical conversation. Opening it occurs only on an explicit user action.
3. Use a transient, click-through, nonactivating `NSPanel` and Core Animation for same-display travel. Source and destination must both remain valid. Screen changes, moved/hidden slots or owner changes cancel presentation or fall back to a fade, without touching admission. Restore the source app only when the capture-owned selector still owns focus; never override a later user focus choice. Read layout in points through view/window coordinate conversion, not guessed scaled pixels.
4. Extend the existing host-owned queue execution result with a bounded text-clue projection from the already-completed current-image inspection. Keep it outside user-editable Session response fields. Include only exact observed person/company words and their short visible excerpts, source/image identity, source hash, producer receipt, pending status and result version. No prose scraping, second model request, face identification, auto-confirmation or contact write. Add optional exact-visible entities to the existing inspection output if its present vocabulary cannot represent company text; retain its existing model and budgets.
5. Expose that projection through authenticated, owner-bound screenshot-message readback. Require the original Session/message/queue/image identity, current source availability and successful host result. The existing metadata-only receipt remains compatible with old clients. Missing/legacy results show an honest no-clue state. Removed/expired/unauthorized sources clear dependent presentation. Do not derive preview data from client-authored response fields.
6. Keep uploading, admitted processing, ready, failed, unknown and cancelled distinct. Scan only after admission, at most twice, then wait statically. A Stop control exists only if wired to the existing governed queue cancellation and terminal readback; otherwise use an accurately named presentation-dismiss action and the ordinary Session's real control. Never label a hidden animation as a stopped Agent. Unknown cancellation/admission reconciles the original operation before replay.
7. Retain only the user-selected image needed by existing preview/recovery and a bounded presentation thumbnail. Preserve existing encrypted recovery/expiry and deletion behavior. Inspect-original actions use that same current source and protected Session; no broad image cache, generic notification content or analytics. Clear presentation on owner/workspace/login changes, source invalidation, dismissal and its retention deadline. A visible ready presentation performs bounded source/authority revalidation; it is not a resident background feed.

Rejected: a six-second success animation; chips inferred from `resultRecorded`; a second model call; a second business queue; a page-callable native bridge; a fixed mock input-frame destination; silent foregrounding of the main window; cross-display travel; face-based identity; relaxed auth/retention/CI gates.

API basis: [NSWindow coordinate conversion](https://developer.apple.com/documentation/appkit/nswindow/converttoscreen(_:)), [backing-scale guidance](https://developer.apple.com/documentation/appkit/nswindow/backingscalefactor), and [CAKeyframeAnimation key times](https://developer.apple.com/documentation/quartzcore/cakeyframeanimation/keytimes). Prefer explicit ordered key times; do not use paced interpolation that discards the intended timing.

## Design amendment A1 — source-bound persistence (before schema changes)

Tracing `conversationQueueState.finalizeConversationQueueEntry` and migration `073_conversation_queue.sql` proved that successful completion sets `content_state=scrubbed` and clears the temporary queue result. The legacy `persisted_at` column is not a current completion authority. Keeping the full result or requiring `retained`/`persisted_at` would violate lifecycle or prevent every real completed result.

Persist only the already-produced, validated <=6-clue observation and its run ID on the original `conversation_message_images` row, atomically with the fenced successful terminal transition before the temporary queue result is scrubbed. Add one nullable, bounded JSON column through a fresh manifest migration; no new table or model call. Cancelled/invalid/legacy results clear or omit this projection. The public readback requires exact current owned Session/message/image/run, real completed canonical turn and available source. It ignores the editable Session JSON for clue content. Source expiry/deletion/cascades remain its retention authority; the native thumbnail/ready surface still has a five-minute maximum. Do not require queue objective/result retention to read an admitted original.

C1–C18 remain unchanged; C16 already permits a migration when proved necessary. Verify real queue finalization, including that its full result is NULL while the bounded source projection survives, then expiry/deletion, wrong owner and forged client fields. This amendment replaces only the initial no-migration storage assumption, not acceptance.

## Design amendment A2 — isolate optional anchor failures

Two real configured-model literal-text calls returned HTTP 200, the expected model and complete exact text/person/company clues, but supplied `kind: organization` in one optional `public_context_anchors` row. Its enum allows only work/role/handle, so whole-object parsing discarded the valid observation. The no-text and group fixtures passed; the failure is schema coupling, not a timeout, missing key or empty OCR.

Keep the existing strict bounded schema, required observation fields, entity validation, top-level unknown-field rejection, provider/model/receipt checks, limits and budgets. At the model parsing boundary only, parse each row of an already-array, at-most-eight optional public-context-anchor list with its strict row schema and omit invalid rows. Never coerce unknown categories, promote them to roles, or relax downstream public-subject provenance. Invalid array type/oversize and invalid required fields still reject. Clarify the producer prompt's existing three anchor kinds, using role for an explicit professional organization/role. This prevents an unrelated optional enrichment from erasing valid OCR while granting invalid enrichment no authority.

Freeze a regression replaying the actual observed response shape: required text and pending visible entities survive, the valid anchor survives and the organization row is omitted; >8 anchors and unknown top-level fields still fail.
