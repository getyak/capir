# GET-140: download and setup experience

## Outcome and boundary

Make `/download` a calm, useful installation hub for Web, macOS, iOS, CLI and
both MCP directions. Reference Claude's direct platform actions and progressive
setup, while preserving capri's relationship-continuity identity. No invented
install links, account grants, native releases or external tool execution.

## Design tree and frozen judgment criteria

D0: A person wants to continue their relationship context from a familiar device
or tool. Understand availability, choose one path, and complete setup without
an invented promise. Connection context and human control are product invariants.

D1-A: One relationship, several entry points. Spatial grammar: one calm canvas,
continuity diagram, grouped device choices. Mechanic: a short path into the same
workspace. Anti-reference: a store grid of indistinguishable app badges.

D1-B: An honest setup desk. Spatial grammar: left narrative, right installation
ledger, visible status and copyable commands. Mechanic: expand exact setup only
when needed. Anti-reference: dense engineering documentation as a hero.

D2-A1: centered continuity hero → device row → terminal/MCP desk → help.
D2-A2: device recommendation → narrative proof → all integrations → help.
D2-B1: installation ledger hero → technical setup → help.
D2-B2: device tabs with a changing main panel → extensions → help.
Retain A1 and B1 as materially different visual prototypes before selection.

Compare rendered evidence for five-second clarity, hierarchy, ownability,
product truth, typography/spacing, responsive craft, interaction feedback,
accessibility, restraint and overall cohesion (10 points each). A separate
reviewer records deductions; the requested >96 is subjective design acceptance,
not a Lighthouse or functional claim. Functional gates stay separate.
