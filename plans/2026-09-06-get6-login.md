# GET-6 login experience

## Outcome

Deliver a brand-specific, responsive login experience based on GET-6's actual
reference images, with polished accessible motion and Google sign-in that
opens a real account-scoped backend session.

## Scope and ownership

Own the iOS authentication entry (primary), Web login adaptation, and minimum Google
authentication path and configuration required for a verified session. Preserve
all existing work, especially the extensive in-progress backend and iOS changes.
No candidate records, external messages, or unrelated product surfaces are in
scope. The user authorized browser operation and Google OAuth configuration.

## Evidence and unknowns

- Current login uses a static photograph and a form in two columns.
- Web Google OAuth is conditional on credentials, but currently provides no
  backend session. A successful Google callback alone does not grant access to
  account-scoped APIs.
- GET-6 was read in the already-authenticated Linear native app after browser
  and API access failed. The three supplied images are still captures of Wabi's
  mobile onboarding: swipe invitation, centered brand emergence, and portrait
  bubbles above two login providers. No original motion video was supplied.
- The issue explicitly requests email as the unique user-facing credential,
  Google support, swipe-led entry, soft portrait collisions, and a connected
  brand transition. The primary implementation is therefore native iOS.
- Infisical owns credentials. Do not save provider secrets in Git or output.
