## Evidence and decisions

- CLI has PKCE, loopback validation, native keyring, cancellation compensation,
  cross-process credential locks and logout clients. Server/Web auth is missing.
- Existing `capir.v1` has `refresh_supported=false`; versioned v2 negotiation is
  required for rotation rather than pretending old credentials support refresh.
- Existing test provisioning is operator-owned and origin/generation bound.
  User test access must be separately admitted by server entitlement, never
  synthesized as the global operator credential. Preserve existing operator
  behavior and exact-run idempotency/recovery.
- Use opaque secret hashes and durable transaction/lock boundaries. Independent
  CLI backing sessions, if needed for canonical revocation, are server-internal;
  only scoped grant credentials reach clients. Browser logout remains independent.
- Proposed TTLs: 60-second code, 15-minute access, 7-day refresh idle and 30-day
  absolute grant lifetime, server-owned. Rotation cannot widen identity/scope.
- Web confirmation must use primary backend identity and session-bound CSRF,
  intentional POST, no-store/no-referrer, existing login/onboarding return.
- Preserve keyring-only storage, CAPIR_TOKEN as ephemeral separate authority,
  origin-pair identity, concurrent CAS semantics and old credential readback.
- Server override priority is explicit flag > CAPIR_SERVER > selected named
  environment. Overrides require an already explicitly configured origin pair;
  discovery cannot add trust, and redirects never carry credentials elsewhere.
