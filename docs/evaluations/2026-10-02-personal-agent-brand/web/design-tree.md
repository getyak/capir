# Personal Agent website direction evidence

## Product invariant

The visitor has just noticed a chat that will matter again: an introduction, a promise, or a change. Understand that one intentionally shared screenshot can produce a short sourced understanding before the user chooses what to retain. Feel relief rather than a new organizing obligation. Try the synthetic interaction; request access only after understanding its limits. The distinctive mechanism is continuity of the same unfinished thing across later evidence, with a visible human gate and source withdrawal.

## D1: Two brand theorems

- A: A lightweight handoff catches the part of a conversation that will matter again. Metaphor: a marginal redline joining source and reviewed result. Spatial grammar: source left, causal seam center, useful response right. Content priority: promise in ordinary words. Signature: review before saving, then a new screenshot updates the same work. Anti-reference: generic AI command center with glowing untyped nodes.
- B: The next conversation starts from the last one. Metaphor: a continuous thread through yesterday, today, and next time. Spatial grammar: horizontal time with one person and one commitment repeated. Content priority: return value. Signature: an existing item changes, never duplicates. Anti-reference: activity dashboard or CRM sales pipeline.

## D2: Architecture forks

- A1: Single-source handoff → human gate → one item changing → person page questions → quiet trust controls → truthful access. Tempo changes from an asymmetrical source/result scene to a dark editorial continuity section, followed by a sparse provenance instrument.
- A2: Oversized promise → five scenario tiles → feature matrix → CTA. Rejected: hides proof and repeats generic SaaS card composition.
- B1: Time thread → tomorrow's meeting → changed background → pause → access. Retained challenger: stronger repeat-use story but requires more first-visit reading.
- B2: Person dossier → chat/source tabs → tasks list. Rejected: front-loads organization before useful understanding.

## D3: Visible prototypes

Open `prototypes.html`: first viewport and representative mid-page for A and B, with 760px mobile collapse. A uses a WeChat-style synthetic transcript and a source/understanding/human gate/continuation seam. B uses three time columns and repeats the same commitment. The prototypes never claim WeChat connectivity or real data persistence.

Desktop evidence: `a-desktop.png`; mobile: `a-mobile.png`. The parent independently rendered both directions for selection. A CLI-generated blank B image was rejected and removed. A desktop first viewport is taller than ideal; production should place promise and proof side by side where feasible and retain a readable compact source/result layout.

## Reference mechanisms (official pages checked 2026-10-02)

- [mymind](https://mymind.com/): low-friction intentional capture before manual organization; do not copy its unrestricted AI-memory promise.
- [Linear](https://linear.app/): prove specific work through concrete product states; do not adopt its dark dashboard identity.
- [Notion AI](https://www.notion.com/product/ai): connect input, reviewed work, and outcome in product demonstrations; do not promise autonomous multi-agent effects.
- [Apple iOS](https://www.apple.com/os/ios/): familiar device controls and clear material hierarchy; no imitation of Apple brand assets.

## Functional gate and judgment

Functional constraints: honest synthetic scope, inspectable exact source, no deadline invention, no silent identity binding, human-reviewed local state, source withdrawal invalidates dependent answers, pause retains context, replay never restores a removed source, keyboard controls, no hidden-page animation, reduced-motion parity, readable mobile/dark layout.

Pairwise judgment pending independent parent review. Preliminary A advantage: its source→plain-language promise is understandable before learning the object model. B advantage: repeated identity of the same item is visually explicit. Proposed combination preserves A's first-visit handoff and uses B's continuity mechanism for the next section.


## Selection and implementation

The parent independently inspected A desktop/mobile and B desktop and selected A as the first-visit argument, with B as the continuity section. The production hero compresses its title and whitespace, places source, directed causal path, and Agent understanding together, and presents a short source excerpt before the Agent result on mobile. Full WeChat-style material expands explicitly.

The signature implementation is a page-local reducer: source admission → attributed understanding → human review gate → separate person/context/work layers → proposed update of item 01. Directed SVG edges and node states reflect actual local transitions. It never claims backend or WeChat execution. The person illustration is a projection of this same state, including source withdrawal, identity ambiguity, and reminder pause.

UI/UX search contributed 44px controls, reduced-motion parity, and restrained simultaneous animation. Its unrelated default palette/font recommendations were rejected in favor of the project's canonical warm neutrals and vermilion. The final anti-template review kept an asymmetric causal proof, a distinct dark time thread, a sparse person projection, expandable everyday stories, and provenance decisions.

Verification: reducer boundary tests, source-removal/identity/pause rendering tests, and localized FAQ tests. Shared localized FAQ content supplies visible FAQ and JSON-LD. Existing recruiting fixtures and historical research stay scoped rather than rewritten into false generic examples. Persistent package, domain, email, storage, and iCalendar identifiers remain compatible.
