## Source-section evidence inventory

The following summaries freeze the relevant claims retrieved in this run.
They are source assertions, not verified implementation behavior.

- S1, 故事起点 / 前端设计重点: intentional screenshot capture; first screen
  covers person, Pursuit, and unresolved saving; identity review uses temporal
  comparison rather than a separate global-search destination.
- S2, 前端还可以更深一层: compress review into identity-owner selection
  followed by relationship attachment; crop highlights reduce explanation.
- S3, 背后的 agent contract: Agent proposes bindings, never silently binds;
  insufficient identity clues can yield no_action or identity_review; a
  raw image used only for the run should not appear to be long-term media.
- S4, 深化补充 / 三种设计方向: the recommended two lanes instead mean
  person/relationship first and proposed changes second; deferred low-risk
  changes must not appear confirmed.
- S5, 子模块合同: SourceEnvelope includes captured-at, speaker, purpose,
  retention, processing boundary; ChangeSet connects old and proposed values,
  evidence, and consequences; ReviewReceipt records decisions and revisions.
- S6, 当前运行证据 / Story eval: the page claims a demo supports partial
  confirmation with unresolved relative dates. It requires zero automatic
  canonical writes for stale identity, revoked sources, or unknown speakers,
  and resumption at the same evidence crop and revision.
- S7, Frontend eval: step count, ambiguous-identity write count, unresolved
  recovery, and user understanding of saved-versus-confirmed states.
