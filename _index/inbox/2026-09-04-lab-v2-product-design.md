## 交付速览：在 iPhone 上的一次完整使用

设计复核：2026-09-05。默认沿用现有 SwiftUI 的暖中性色、克制朱红、原生导航
和分组列表。首页承担概览，下面只有任务入口；长参数表、原始 trace 和技术字段
放到详情。每个入口先说明能做什么，再显示运行条件。

最有价值的一条路径是：打开“AI 实验” → 选“身份歧义时应先澄清” → 固定同一
合成案例和提示词，只换模型 → 看两份实际输出及逐项检查 → 从错误保存回归案例
→ 修复后复测 → 检查该案例是否确实被发布流程执行。更快但擅自绑定身份的配置
仍判定不通过。合格的配置可以进入当前测试会话，首页持续显示覆盖及恢复默认入口。

日常设备任务保持独立可达：“环境与版本”验证并切换已部署目标；“外观与体验”
在真实页面测试字号、主题和异常状态；“性能与诊断”引导复现并展示耗时区间；
“数据与重置”按目的列出影响、保留项和结果。离线与退出登录后仍保留本地入口。

交互预览覆盖首页、实验配置与恢复、结果与回归、环境预检、外观预设、诊断报告、
重置影响清单，以及空白测试工作区的进入/返回。预览使用明确标记的合成状态，
不会调用模型、切换实际后端或清理设备。它表达目标交互；实际已交付能力和待办
仍只由[完整实现计划](../../plans/2026-09-04-lab-complete-runtime.md)记录。

## 1. 产品定位与完成标准

Lab 的工作是缩短这个循环：发现问题 → 固定条件 → 改一个变量 →
观察真实结果 → 判断是否改善 → 保存证据 → 验证下一次没有退步。

它也应解决内部测试中每天发生的小事：确认连了哪台服务、换一个已部署版本、
检查大字体、定位慢在哪里、清理可重建缓存、重新登录、重走首次体验。

主用户是产品负责人、设计者、开发者和内部测试者。普通用户继续使用正常产品；
Lab 中产生的实验不应变成他们需要理解的新工作流。

每个功能必须能回答四个问题：

1. 我想解决什么具体问题？
2. 我改变的是哪一项，影响哪一个范围？
3. 操作完成后，我能看到什么证据？
4. 失败、退出或重启后，怎样恢复？

建议用这些任务验收整个设计，以下时间是待实测的体验目标：

- 10 秒内知道当前 App、后端、账号、实际模型和临时覆盖状态。
- 30 秒内准备好一次真实模型对比；执行时长由实际服务决定。
- 无需 Xcode，完成外观检查、查看请求摘要和清理可重建缓存。
- 后端不可用、已退出登录时，仍能进入本地诊断和恢复功能。
- 从一次失败结果直接保存复现条件，修复后在同一案例上复测。

## 3. 成熟项目怎样解决这些问题

这里选择的是相关领域的成熟参考，不是未经测量的“项目排名”。以下产品能力
来自官方资料，右列是对 Talent Signal 的设计推论；不意味着需要安装全部工具。

| 参考 | 官方能力 | 借鉴到 Lab 的方式 |
| --- | --- | --- |
| [Langfuse Playground](https://langfuse.com/docs/prompt-management/features/playground) | 编辑 prompt、模型参数，并排运行变体；可从生成记录进入 Playground | 从产品中的某次回答直接创建实验；编辑内容形成新版本 |
| [LangSmith 实验比较](https://docs.langchain.com/langsmith/compare-experiment-results) | 在同一数据集比较实验、筛选退步案例、查看输出差异及 trace | 首先显示哪些案例退步，再展开平均指标和详细执行路径 |
| [Promptfoo assertions](https://www.promptfoo.dev/docs/configuration/expected-outputs/) | 程序断言、模型辅助评估、成本和延迟指标 | 把结构正确、证据正确、边界正确与文案质量分开测量 |
| [Expo development builds](https://docs.expo.dev/develop/development-builds/introduction/) | launcher 可切换开发服务器和部署，提供开发菜单与网络检查 | 使用清晰的运行配置入口；SwiftUI 产品仍需要自己的原生实现 |
| [FLEX](https://github.com/FLEXTool/FLEX) | 原生 App 内检查视图、网络、沙盒和 defaults；官方明确要求排除 Release | 借鉴设备内诊断；完整反射和任意状态修改仅评估用于本地 Debug |
| [Pulse](https://github.com/kean/Pulse) | 可嵌入 SwiftUI 的日志和 URLSession 请求检查、日志分享 | 内测版可以评估接入经过脱敏的请求控制台，不默认采集正文 |
| [Storybook Controls](https://storybook.js.org/docs/essentials/controls) | 交互修改组件输入，观察不同状态 | 建立原生页面与组件状态目录，不在 SwiftUI 中照搬 Web runtime |
| [Xcode 外观检查](https://developer.apple.com/documentation/xcode/diagnosing-issues-in-the-appearance-of-your-running-app) | 外观、文字大小及辅助功能环境覆盖 | 在 Lab 中提供可恢复的 App 内预览；系统级验证仍借助系统设置/Xcode |
| [Apple Instruments](https://developer.apple.com/videos/play/wwdc2025/308/)与[MetricKit](https://developer.apple.com/documentation/metrickit?language=objc) | 分析执行区间、CPU，以及实际设备性能和诊断报告 | App 内负责记录任务时间线和引导；深入采样交给专业工具 |

共同点是把测试条件、执行结果与下一次改进连接起来。我们的重点应当是自己的
产品闭环，而不是把这些工具的所有能力塞进一个菜单。

## 4. iOS 信息架构

建议名称仍为 **Lab**，副标题为“实验与调试”。采用原生分组列表、简短摘要和
逐级详情；不做六个底部 Tab，也不做铺满数据卡片的仪表盘。

| 一级入口 | 用户问题 | 第一屏主操作 |
| --- | --- | --- |
| 概览 | 我现在运行的是什么？哪里有异常？ | 开始实验 / 继续上一次任务 |
| AI 实验 | 换模型、提示词或流程后，结果更好吗？ | 新建对比 |
| 环境与版本 | 当前连接哪里？换哪个已部署版本？ | 查看并切换运行配置 |
| 外观与体验 | 真实页面在不同状态下好用吗？ | 进入页面预览 |
| 性能与诊断 | 这次卡顿或失败发生在哪一段？ | 开始一次诊断 |
| 数据与重置 | 我要重新测试，需要清理什么？ | 选择清理或重新开始任务 |

内部版本在设置中提供明确入口。需要快速往返时，可在产品中固定一个小型
“正在测试”入口；只在实验覆盖生效时显示环境/覆盖提示，点开查看详情。
不要求记住摇一摇、连续点击版本号等隐藏手势；手势可以是补充快捷方式。

登录页也应有内部 Lab 入口。本地模块是否存在由构建能力决定，远程模块再由
服务器和身份决定。这样服务器断连时仍能查看配置、清缓存、清理登录及导出诊断。

概览优先显示：

- App 版本、build、分发渠道、iOS 和设备类型。
- 后端环境、实际部署 revision、兼容状态、最后一次验证时间。
- 账号/工作区的最小识别信息、登录状态；凭据只显示状态。
- 本次任务实际使用的模型与 prompt 版本；尚未运行时显示“尚无实际运行记录”。
- 当前覆盖：主题、模型、网络故障模拟等；每一项都有作用域与退出入口。
- 最近一次实验、失败请求、未完成诊断，按可处理性呈现。

“配置要求使用哪个模型”和“这次实际由哪个模型执行”必须分别显示。
后端失联时旧信息带时间及“上次已验证”标签，不能显示为当前健康状态。

## 5. AI 实验：让它真的检验模型和产品

### 5.1 三种运行方式

| 方式 | 输入与执行 | 能证明什么 |
| --- | --- | --- |
| 演示与确定性检查 | 固定合成内容、固定工具响应、预设输出或确定性执行器 | 页面状态、协议和回归规则工作正常 |
| 真实模型实验 | 合成或已批准用于此用途的输入，调用真实模型，按任务固定上下文 | 在已声明条件下的真实输出、耗时、用量和质量差异 |
| 产品流程实验 | 在隔离测试工作区，从实际产品入口走到审阅/结果 | 模型、后端、UI、恢复一起工作时，测试者能否完成任务 |

首个版本开放“合成数据 × 真实模型”，就能开始得到价值。真实业务案例以后经
单独选择、内容审阅、用途和提供方范围确认才能进入实验；匿名化并不自动消除
授权要求。通用日志不承担实验输入库的职责。

Lab 的“真实”指真实执行和测量，不要求使用真实候选人数据。

### 5.2 新建实验的操作流程

1. 选择任务：“从截图审阅联系人”“判断是否需要澄清”“生成有依据的回答”
   “给出下一步或 no_action”等。任务先于模型选择。
2. 选择输入：单个合成案例、小型案例集，或从一条合成失败记录创建案例。
3. 选择对照配置 A 与待测配置 B。默认只改模型、prompt、后端或流程中的一项。
4. 展示差异、输入范围、调用次数、重复次数、费用上限和工具访问范围，点击运行。
5. 看产品实际会显示的结果，展开原始依据、校验、trace、时间和用量。
6. 标记“更好 / 更差 / 相当 / 无法判断”，记录具体错误类型及需要改进的行为。
7. 保存实验，选择“从失败创建回归案例”或“在我的隔离测试会话中试用”。

手机适合比较 A/B 两个配置、检查少量案例；大型矩阵、长 prompt 编辑、批量标注、
趋势和发布审批放到 Web。iOS 必须仍能独立完成一次有价值的真实对比。

### 5.3 模型选择要按任务显示

不提供一个会悄悄改变所有能力的全局模型开关。模型选择绑定任务或明确的
运行配置，显示 provider、固定模型 ID、可用状态以及任务所需能力：文字、
图片、结构化输出、工具调用。语音转写若属于独立服务，应有独立配置。

能力不兼容时解释原因，不能把不支持图片的模型静默用于图片实验。
新模型的接入及凭据管理放在服务端/受控 Agent Host；手机只持有配置引用。
实验默认影响本次运行，可显式扩展到当前内部测试会话，不能改变所有用户默认值。

推理参数按 provider 能力呈现；不向每个模型都强塞 temperature、seed 或
reasoning effort。请求的配置、服务端解析后的配置和实际返回的模型 ID 全部留档。
拒绝静默回退；若任务允许降级，结果需明确标记且不得混入原配置对比。

### 5.4 什么叫“变好”

先定义期望行为，再运行。一个实验至少回答：

| 维度 | 例子 | 判断方式 |
| --- | --- | --- |
| 任务完成 | 截图线索形成可审阅联系人卡，而非只生成一段总结 | 结构检查 + 人工任务验收 |
| 证据忠实 | 每个重要断言都能找到当前有效的对应证据 | 确定性引用检查 + 内容审阅 |
| 不确定性处理 | 身份不明时澄清、来源冲突时保留冲突 | 按案例的预期结果检查 |
| 权限和边界 | 不自动合并、不恢复撤销来源、不擅自写外部系统 | 独立硬性检查 |
| 易用性 | 测试者理解结果，减少纠正和无效往返 | 盲评、完成时间、纠正次数 |
| 速度和稳定性 | 首个可用结果、最终完成、超时、限流、失败 | 实测时间线与终态 |
| 费用 | 输入/输出/缓存 token 和可核实的费用估计 | provider 用量及带版本的费率 |

硬性失败不能被“表达更好”或“更便宜”的平均分抵消。模型辅助评分只做线索，
显示评判模型、rubric 和证据；裁判不确定时进入人工审阅。不得评分人的价值、
人格或录用可能性。人工偏好也不能单独证明事实正确。

结果首屏用可行动的结论，例如：

> 待测配置速度更快，但两个身份歧义案例出现不当绑定建议。暂不推荐替换。

这只是文案示例，实际结论必须来自测量。展示通过/失败/跳过/未知的数量，
并能直接打开退步案例。信息不足时显示“证据不足”，不强选赢家。

### 5.5 保证比较有意义

每次实验冻结输入、案例修订、上下文、时区/参考时间、prompt 及输出 schema、
工具清单、检索条件、后端部署、模型解析结果、评判规则和仪器版本。

单变量实验只改变指定项；多变量实验可以存在，但明确标为“整体方案比较”，
不能把提升归因于某一个模型。固定输入使比较条件一致，不意味着真实模型输出
可以逐字复现。

首先运行 1 个案例验证线路，再用例如 20 个案例 × 每配置 3 次作探索性比较。
这是起步方案，不是统计保证。重复同一个案例不能算成多个独立业务案例。
保留失败与超时，交错运行 A/B，说明冷/热缓存和网络条件；数据不足时不报告
貌似稳定的尾延迟或显著性结论。

保留独立未调参案例集；目标模型不读取标准答案和裁判输出。更换案例集或裁判
版本后，应重新运行对照，不能把历史总分当作直接可比结果。

有外部检索时，区分“固定工具响应的对照”与“真实实时检索的全流程测试”。
后者保存授权范围内的最小来源版本/时间信息，并承认外部状态变化会影响比较。

### 5.6 运行中的控制和恢复

后台服务拥有长实验的 job，手机只启动、观察和恢复。退出页面、锁屏或网络断开
后，重新进入通过 run ID 查询状态；不因丢失响应再次发起付费执行。

状态包括排队、执行中、部分完成、完成、取消中、已取消、失败、结果未知。
取消先停止未开始的工作；已经发往 provider 的请求可能仍完成并计费，需单独
报告。预算按服务器实际执行前的预留和并发限制控制，包括裁判调用；供应商不
提供用量时显示未知而非零。

真实模型调用会产生网络传输和可能的费用。因此“0 external effects”需要拆为：
业务写入为零、模型调用若干次、费用已知/估计/未知。不能把付费外发描述为
完全没有外部影响。

## 6. 环境与版本：切换的是可验证的运行上下文

### 6.1 运行配置

一个配置包含环境 ID、允许的 endpoint、部署 ID、API 兼容范围、工作区类别、
允许的模型配置以及认证方式。示例名称是“本机测试”“内部稳定版”“PR 预览”。

后端列表来自受控部署目录；每行显示健康状态、实际 build/revision、更新时间、
数据域和兼容性。不可达的版本可以被查看，不能被展示为可用。

“选择后端版本”首先意味着连接一个**已经部署**的目标。部署一个 Git revision、
升级数据库和选择 endpoint 是不同任务。建议先支持前者的连接选择；部署管理
后续放 Web。App 原生二进制版本也不能通过这项设置热切换，需要安装相应构建。

同一数据库上的两个部署切换只能比较代码，不能当作数据恢复或数据库回滚。
旧后端不兼容当前 schema 时不进入可选列表。后端回滚需要单独的发布流程。

### 6.2 一次完整切换

1. 选择目标，预检允许域名、TLS、部署身份、协议及登录方式；预检不带原环境凭据。
2. 展示“当前 → 目标”及草稿、后台实验、上传/录音等正在进行的工作。
3. 为已接受的服务端操作保存原环境 operation ID；未决写入进入恢复任务，
   不向新环境重发。录音、上传等需先结束或明确处置再切换。
4. 原子切换整个客户端运行上下文，销毁原网络 client 和易失视图状态。
5. 使用目标环境独立凭据，必要时重新登录；验证工作区后才展示内容。
6. 显示实际部署及“已切换”回执。失败时停留原配置或明确进入待登录状态。

凭据、缓存、草稿、实验恢复和截图队列绑定环境+账号+工作区；切换不迁移数据。
尚未绑定账号的分享输入保持未分配，后续显式选择归属。旧响应带上下文世代标识，
即使晚到也不能渲染到新环境。所有敏感网络请求防止跨域重定向带出凭据。

自定义 endpoint 仅为本地 Debug 的高级能力，并保持原有回环 HTTP 例外；
内测分发版使用批准的 HTTPS 目标。不得为了切换方便关闭证书验证。

### 6.3 功能开关

显示“服务端值 / 本机覆盖 / 实际生效值 / 到期时间”。只开放有名字、
有依赖校验的产品实验开关；保存为可版本化预设。权限、身份确认、删除、
数据隔离等约束不作为可关闭的实验选项。

## 7. 外观与体验：在真实页面里验证

两个入口：“当前页面临时调试”和“页面状态目录”。优先复用实际 SwiftUI 组件，
由合成数据适配器控制状态，避免维护一套长得相似的假页面。

| 可调内容 | 使用方法 |
| --- | --- |
| 浅色/深色/跟随系统 | 临时覆盖当前测试会话，退出可恢复 |
| 中英文、长文案、动态字号 | 对比截断、换行、按钮和输入框高度 |
| 卡片密度、有限的间距和排版 token | 使用受约束的设计参数，保存试验预设 |
| 减弱动画、减少透明度、高对比度的 App 内响应 | 明确标记模拟；系统实际状态另行验证 |
| 加载、空、失败、部分数据、长姓名、过期来源 | 在同一真实组件中切换受控场景 |
| 点击区域、布局边界、baseline 等覆盖层 | 默认关闭；仅用于诊断且不进入正式截图 |
| 两个已编译的交互版本 | 比较导航/审阅流程，记录理解和完成任务的差异 |

预览范围显示为“仅此页面 / 当前测试会话”。“保存为我的显示偏好”与
“保存为实验预设”是两个动作；临时拖动参数不会修改其他用户设置。
动态字号和密度独立，不能通过缩小点击区域或压低辅助功能字号制造整齐。

手机可以检验本机真实尺寸；其他设备宽度的容器预览只能表示近似布局，
不能冒充另一台设备的完整渲染。VoiceOver 和系统权限表现要在真机/Simulator
实际设置下验收，不能因 App 内模拟状态正常就宣布通过。

截图或录屏默认选合成页面；真实页面需单独确认内容范围，先预览脱敏结果。
只截取当前 App，排除键盘输入、token 等敏感内容；后台时停止记录。

## 8. 性能与诊断：从用户症状进入

第一屏的问题应该是：“哪里感觉慢？”提供“打开应用”“打开联系人”
“发送文字/截图”“开始录音”“列表滚动”“请求失败”等任务。

一次诊断流程：选择任务 → 显示准备条件 → 开始记录 → 手动复现 →
结束 → 看时间线与可能原因 → 保存报告 / 查看下一步工具指引。

文字或图片任务时间线可分为：本地准备 → 排队/上传 → API → 上下文读取 →
模型首个结果 → 模型完成 → 校验/持久化 → UI 可交互。
分别记录首个可用内容和最终确认，避免只测首 token 后宣称整个流程很快。

| Lab 内可观察 | 使用边界 |
| --- | --- |
| 单调时钟计时、signpost 区间、请求状态、重试次数 | 无正文日志，使用封闭事件名和关联 ID |
| URLSession 阶段、服务端 trace 区间、token 用量 | 两端通过 ID 关联，不直接相减未经同步的墙上时钟 |
| 帧节奏采样、内存及热状态等受支持指标 | 显示采集方法；近似帧率不等于已定位 GPU 原因 |
| MetricKit 历史性能和诊断报告 | 性能聚合通常覆盖前 24 小时且至多每天交付一次；不能当实时读数 |
| 缓存使用、读取命中、资源解码耗时 | 记录冷/热状态和样本数，不偷偷清缓存来改善结果 |

更深入的 CPU、内存泄漏或渲染分析提供 Xcode/Instruments 操作指引及对应
signpost 区间。Lab 不声称能在 TestFlight 里启动完整 Instruments。
MetricKit 的指标交付与诊断交付不同，详见 [Apple 官方说明](https://developer.apple.com/documentation/metrickit?language=objc)。

问题报告先展示观察，例如“主要耗时位于模型请求区间”；“模型服务慢”是待验证
判断，不能忽略网络、排队和客户端处理。诊断开销也要记录，重测试用同等条件。

故障模拟提供命名预设：离线、额外延迟、首次 401、一次 429、一次 500、响应
中断、过期证据。只作用于隔离测试的网络适配器并带到期时间；不通过停真实
服务器、删除真实来源或伪造系统授权来制造故障。

本地日志采用有界存储与短保留窗口，记录前即脱敏。默认排除 token、cookie、
查询参数中的身份信息、请求/响应正文、截图、音频和转写。导出前显示预览与
内容清单；“诊断包已导出”和“问题已提交”是不同状态。

## 9. 数据、登录与 onboarding：按目的重置

保留单项操作，也提供引导式组合操作。每次破坏性操作只在最终影响清单处确认，
可重建缓存的常规清理保持轻量，不连续弹窗。

| 用户操作 | 实际范围 | 不能误报的事情 |
| --- | --- | --- |
| 清理图片/网络缓存 | 已列明、可重建、当前作用域的缓存；显示估计/实测释放量 | 不清未上传原图、音频、审阅队列、草稿和未决操作日志 |
| 重新获取工作区 | 使投影缓存失效并重新读取 | 不删除服务器联系人或来源 |
| 清理诊断记录 | 本机日志、受控截图、性能记录，保留非内容操作回执 | 不清实验定义或业务证据 |
| 恢复外观默认 | 本机显示偏好与临时覆盖 | 不改变系统辅助功能设置 |
| 退出当前环境账号 | 清除本机相应会话并尝试服务端撤销，关闭该账号内容视图 | 不退出系统 Apple ID、不删除账号；远端撤销失败要显示 |
| 重新体验 onboarding | 重置 App 自己的引导进度或开启隔离预览 | 不表示账号已成为新用户，也不会重置系统权限 |
| 新建空白测试工作区 | 服务端创建一个明确标记的隔离测试空间 | 不清空原有工作区来冒充新用户 |
| 重置当前 Demo | 只重置明确列出的 Demo 数据和 Demo 活动 | 不影响真实捕获、联系人、日历或用户快捷指令 |
| 重新开始本机测试 | 组合选择恢复显示、清缓存、退出指定会话、重置引导；新建测试空间可选 | 不使用不透明的“清空一切” |

“重新开始本机测试”的确认页展示环境、账号、将清理的类别、保留的待处理内容、
系统权限现状，以及完成后落到哪里。默认保留 Lab 的受信环境目录，以免把恢复
入口一并删掉。已有未决写入时，应先完成同 ID 对账，或隔离并保留恢复日志，
不能将日志当缓存清掉后重新提交同一操作。

破坏性步骤生成本机操作 ID，幂等执行并逐项校验。中途崩溃后恢复未完成项，
部分失败显示“清理未完成”及可重试项。退出登录后须验证旧内容、快捷入口和
恢复草稿均不再显示，重新登录并确认原工作区后才可恢复保留内容。

系统权限要单独讲清楚：App 可以读取相关授权状态并引导打开设置，不能自行
恢复麦克风、照片或 Apple 登录首次系统弹窗。在 Simulator 可按测试指引重置
权限，真机操作遵循系统支持方式；不要为了重看一个引导要求用户重置整台设备。
参考 [Apple 隐私权限说明](https://developer.apple.com/documentation/uikit/requesting-access-to-protected-resources?changes=_5_3&language=objc)
和 [Simulator privacy 工具说明](https://developer.apple.com/documentation/Xcode-Release-Notes/xcode-11_4-release-notes)。

## 10. 从实验到改进，再到发布

```mermaid
flowchart LR
  A[真实任务中发现问题] --> B[选择并审阅可用于测试的输入]
  B --> C[冻结案例和配置 A/B]
  C --> D[真实执行与测量]
  D --> E[查看退步案例与人工判断]
  E --> F[保存失败条件为回归案例]
  F --> G[修复后复测同一案例集]
  G --> H[独立验证与发布评审]
  H --> I[内部小范围试用与结果观察]
  I --> A
```

问题记录从“只有结构化预设记录”扩展为受控报告：期望行为、实际结果、场景、
配置差异、错误分类、诊断关联和可选的审阅备注。备注不默认包含原始对话，也
不自动送给模型。敏感附件使用单独的选择、审阅、保留和删除流程。

“保存案例”与“纳入发布检查”独立。要宣称门禁生效，必须看到该版本案例已被
CI/发布流程消费、实际执行及其裁决；仅数据库标了 blocking 不够。

实验预设通过后，可以“仅在我的测试会话启用”。改变团队默认模型、生产环境
配置或放量策略需要独立发布权限和评审。显示候选配置、通过/未通过的检查、
回退目标和观察窗口。Lab 不因实验得分更高就自动切换所有用户。

后续再考虑产品 A/B 分组：预先定义任务完成指标、分配规则、最小样本、保护指标
和停止条件，按工作区隔离实验，观察纠正率、完成时间、恢复成功率等实际收益。
这属于在线实验，不与离线 A/B 输出对照混称。内部试用数据不足时不做因果承诺。

## 11. 工程结构与分发能力

建议保留一个入口，但拆成三个拥有明确职责的层：

| 层 | 所有者和对象 | 职责 |
| --- | --- | --- |
| Device Lab | iOS；DisplayOverride、DiagnosticSession、ResetOperation | 本地外观、诊断、存储与恢复，离线可用 |
| Runtime Context | iOS + 后端目录；EnvironmentProfile、DeploymentManifest、CapabilityManifest | 统一 endpoint、身份和实际生效配置，完成原子切换 |
| Experiment Service | 后端 + 受控 Agent Host；CaseRevision、ExperimentSpec、Run、Evaluation、Report | 冻结输入、真实执行、预算、评估、恢复及回归证据 |

复用既有案例、trace、评测、provider 和 Agent runner。已有固定 Lab 模式保持
兼容并标记 deterministic；真实模式使用独立执行类型，不能把旧的“重新生成
预设输出 hash”校验直接用于非确定性结果。

“产品流程实验”的 canonical 写入只能发生在明确的隔离测试工作区；纯模型
对照保持业务写入为零。模型调用、检索读和业务写入分别统计。所有提供方仍
只能接收当前任务允许的最小内容，不因进入 Lab 获得数据库或任意工具权限。

运行输入按修订不可变，但删除请求不能被“冻结”阻止：内容可加密删除/撤销，
保留不含内容的 lineage，相关运行标记不可重放。撤销后禁止新调用；已发出的
调用不能承诺撤回，需记录状态并遵循 provider 删除能力。

| 构建/权限 | 可开放的能力 |
| --- | --- |
| 正常发布版本 | 常规产品设置、用户支持需要的有限诊断；不开放内部实验覆盖 |
| 内部 TestFlight 构建 | 公共 API 实现的本地 Lab、允许列表环境选择；远程实验再受服务端权限约束 |
| 本地 Debug | 在上述基础上，评估 FLEX、开发 endpoint、Simulator 调试指引 |

构建身份、账号权限和服务端能力分别核对。不要只靠隐藏入口或客户端开关授权。
TestFlight 不等于 Xcode Debug；FLEX 的完整能力不要随 Release/TestFlight 打包。
单纯本地清理不依赖远程登录，但无法借此提升远程权限。

## 12. 建议交付顺序

避免把“先建平台”变成长期借口。第一批同时交付立刻有用的设备工具和一个真实
模型实验，后续逐步加深。

| 阶段 | 完整交付内容 | 必须拿到的证明 |
| --- | --- | --- |
| 第一批 A：每天能用 | 离线/登录页 Lab 入口、真实版本概览、限定缓存清理、退出登录、引导重播、主题/字号临时预览 | 断开后端仍可使用；清理结果可核实；未上传资料和待恢复操作保留 |
| 第一批 B：一次真实比较 | 一个真实产品任务、两个批准配置、合成案例、真实执行、输出/引用/耗时/用量对比、保存失败 | 显示 provider 运行证据；断网后恢复同一个 run；明确失败与未知 |
| 第二批：可切换可复现 | 原子环境切换、任务级模型/prompt 预设、案例集重复执行、guided diagnosis、命名故障预设 | 换环境无凭据/草稿串用，退步案例可定位，故障退出可恢复 |
| 第三批：持续改进 | 原生页面状态目录、问题转回归、Web 批量比较、CI 门禁、内部试用与回退 | 被保存的失败在修改前失败、修改后通过，发布流程确实运行该检查 |
| 后续：在线实验 | 小范围受控分配、观察窗口与实际工作收益 | 有充分样本及明确归因边界，能停止和回退 |

第一项真实模型实验建议选择“截图 → 联系人审阅卡”：它复用了核心产品入口，
同时能观察视觉理解、身份歧义、字段依据、等待体验和人工纠正。但若当期只有
文字模型通过能力验证，应先交付真实文字任务，图片模式明确不可用。

首个案例集保留现有五种边界，并补充：证据不足、无需动作、过期日期、中文
相对时间、截图只含照片、图片/文字冲突、提示注入、多轮纠正，以及 provider
超时/限流。确定性边界测试与模型语义评估分开显示。

## 13. 设计验收与未决事项

实现阶段至少验证以下失败路径：

- 后端关闭时进入本地 Lab，查看当前配置并重新登录。
- A 环境请求晚到、切到 B 环境后不显示 A 的数据；返回 A 能对账原操作。
- 目标版本协议不兼容、证书不可信或模型不支持图片时，说明原因且不静默降级。
- 真实实验超时/取消/重复点击/锁屏后，保持任务 ID，成本与未知状态不丢失。
- 模型结果更流畅但违反身份边界时，不能靠其他高分抵消失败。
- 清缓存不删除截图 FIFO、音频草稿、未上传文件及未知写入恢复记录。
- 退出登录的本地删除与远端撤销分别显示；部分失败后重启不假报完成。
- 引导重播与系统权限状态一致，已授权时不伪造首次授权结果。
- 外观覆盖有退出方式，大字、深色和减弱动画下保留完整语义与可操作性。
- 诊断包默认没有原始对话、密钥或身份正文；无权限者看不到他人的实验记录。
- 从问题创建的案例在真实 CI 中被执行，未接线时显示“尚未纳入发布检查”。

本提案已按产品价值、证据、状态恢复、provider 中立性和能力真实性做设计层审阅；
这不替代实现后的真机、真实服务和无障碍验收。

后续实现前需要盘点实际部署和已批准模型，并确定首批任务、允许的预算、内部
构建能力以及诊断保留窗口。当前设计不依赖用户先列出所有这些值，界面可以
按能力显示“未配置 / 不兼容 / 不可达”。

首批方向已由 [ADR 0012](../../docs/decisions/0012-useful-device-lab-and-real-experiments.md)
承接。本文保留完整目标设计；功能验收、未完成项和发布边界以实现计划及其链接的
运行证据为准，不能将本提案或交互预览当作全量实现证明。
